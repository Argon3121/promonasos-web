# ТД «Промоборудование» — промо-сайт на Spring Boot

Информационный сайт поставщика промышленных насосов и производителя торцовых
уплотнений: каталог 45 марок насосов (11 конструктивных групп) и 14 типов
торцовых уплотнений, подбор по рабочей точке / параметрам, база знаний, форма
заявки.

## Стек

- Java 21, Spring Boot 4 (Web MVC, Thymeleaf, Validation)
- Maven (Maven Wrapper — отдельно ставить Maven не нужно)
- Данные — статичные списки в памяти (репозитории), без базы данных: контент
  сайта не меняется в рантайме, СУБД была бы лишней прослойкой
- JUnit 5 — тесты на алгоритмы подбора

## Запуск

```bash
./mvnw spring-boot:run
```

Сайт поднимется на `http://localhost:8080`.

```bash
./mvnw test
```

## Структура

Слои названы по-английски (стандартный для Spring MVC каркас: `model` →
`repository` → `service` → `controller`), а классы внутри — транслитерацией
русских терминов предметной области, без промежуточного перевода на английский:

```
model/        MarkaNasosa, ModelNasosa, Uplotnenie, ZaprosPodboraNasosa, ...
repository/   NasosyRepository, UplotneniyaRepository, ... — каталог в памяти
service/      NasosyService, UplotneniyaService — в т.ч. алгоритмы подбора
controller/   NasosyController, UplotneniyaController, GlavnayaController, ...
util/         Chisla — форматирование чисел и склонение по числу в текстах
```

Шаблоны (`src/main/resources/templates`) и статика (`static/css`, `static/js`)
организованы по тому же принципу: `nasosy/`, `uplotneniya/`, `blog/`,
`fragments/` — общие `header`/`footer`/`cta-block`.

## Ключевые решения

- **Без БД и ORM.** Каталог — конечный, редактируется через код, а не через
  админку; JPA и репозиторий поверх БД добавили бы слой без пользы.
- **Без DTO/ViewModel-обёрток.** Spring MVC кладёт данные в `Model` напрямую;
  отдельный класс на каждую страницу — это на 80% лишний список геттеров.
- **Подбор насоса** — не точный инженерный расчёт, а ранжирование каталога по
  отклонению от рабочей точки (`NasosyService.podobratNasos`): у насоса есть
  кривая Q-H, а в каталоге хранится одна номинальная точка, поэтому результат
  — это направление, которое инженер проверяет и уточняет, а не готовый ответ.
- **Подбор уплотнения**, наоборот, работает строгой фильтрацией по диапазонам
  (вал, давление, температура, среда) — тут параметры дискретные, и
  «почти подходит» для уплотнения означает «не подходит».
- **Изображения** — реальные фотографии с открытой лицензией (Wikimedia
  Commons), список источников и авторов — на `/istochniki-izobrazheniy`.

## Тесты

`src/test/java` — модульные тесты на оба алгоритма подбора
(`NasosyServiceTest`, `UplotneniyaServiceTest`): проверяют точное совпадение,
отсечение результатов за пределами диапазона и фильтрацию по среде. Тесты
работают напрямую с репозиториями (без Spring-контекста) — сервис в этом
проекте не требует поднятия контейнера, чтобы протестировать бизнес-логику.
